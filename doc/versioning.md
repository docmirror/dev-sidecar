# 版本号与自动更新规则

## 版本格式

`<major>.<minor>.<patch>[-<label>.<n>]`

预发布标签的优先级从低到高：

```
alpha < beta < dev < rc < 正式版
```

同一标签内，数字段按数值比较：`beta.100 > beta.99`，`alpha.10 > alpha.9`。
不同标签之间按 ASCII 比较标签名，因此上面的顺序成立。

## 各版本的来源

| 标签 | 来源 | 示例 |
| --- | --- | --- |
| `dev` | 本地开发构建，注入工作区指纹 | `2.3.3-dev.a1b2c3d` |
| `alpha` | fork 仓库的 CI 发布 | `v2.3.3-alpha.123` |
| `beta` | `release*` 分支的 CI 构建 | `2.3.3-beta.812` |
| `rc` | 候选版本，手动发布 | `2.3.2-rc.1` |
| 正式版 | 官方仓库 `v*` 标签发布 | `2.3.3` |

## 更新策略

- 只升不降：比较结果小于等于 0 时不提示更新。
- 正式版用户不会收到预发布版本（`-alpha` / `-beta` / `-dev` / `-rc`）。
- 预发布用户会收到比当前更高的预发布版本，以及正式版。
- 本地 `dev` 版本比同号 `beta` 新（不会提示升级到 beta），比同号正式版旧（会提示升级到正式版）。

## CI 发布

- 官方仓库（`docmirror/dev-sidecar`）的 `v*` 标签构建创建草稿 Release，标题就是标签名。
- fork 仓库的同一套工作流会把标题改成 `vX.Y.Z-alpha.<run_number>`，创建草稿后标记 `prerelease`，不会占用 latest，也不会被正式版用户的更新检查选中。
- 资产命名：
  - 完整安装包：`DevSidecar-<version>-<platform>-<arch>.<ext>`
  - 增量包：`update-<platform>-<arch>-<version>.zip`
  - 平台取值 `win` / `mac` / `linux`，架构取值 `x64` / `ia32` / `arm64` / `armv7l`
- 自动更新的回退规则：增量包缺失时改用完整安装包；Windows 安装目录不可写时请求 UAC 提权，由提权进程解压增量包并重启应用，取消授权则中止本次更新。

## 注意

- 未登录的 GitHub API 每小时限流 60 次，频繁点“检查更新”可能触发限流提示。
- 预发布版本之间比较依赖 CI 的 run_number 递增；手工拼出的版本号如果不符合上述顺序，会被判为旧版本。
